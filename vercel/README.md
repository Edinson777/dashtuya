# Вариант Vercel — дашборд с живым опросом Tuya Cloud

Статичный дашборд + одна serverless-функция. Без базы данных, без Actions и коммитов данных: при каждом открытии страницы функция `/api/readings` сама опрашивает Tuya Cloud — берёт текущий статус устройства и журнал отчётов за 24 часа, отдаёт готовый JSON.

```
vercel/
├── api/
│   └── readings.js   # serverless-функция: Tuya Cloud → JSON (без зависимостей, Node 18+)
├── index.html        # дашборд (тот же дизайн, что и у GitHub Pages-версии)
├── style.css
├── app.js            # читает ./api/readings, автообновление раз в 5 минут
└── README.md
```

Формат ответа идентичен `data/latest.json` из Pages-версии — один и тот же фронтенд, разный источник данных.

## Деплой через сайт Vercel (5 минут)

1. Залейте репозиторий на GitHub (уже сделано) и откройте [vercel.com/new](https://vercel.com/new) → **Import Git Repository** → выберите `Edinson777/dashtuya`.
2. В разделе **Root Directory** укажите `vercel` (фреймворк определится как *Other*, сборка не нужна).
3. **Deploy** — получите адрес вида `https://dashtuya-xxx.vercel.app`.
4. **Project → Settings → Environment Variables** — добавьте переменные и сделайте **Redeploy**:

| Переменная | Значение |
| --- | --- |
| `TUYA_CLIENT_ID` | Access ID проекта Tuya Cloud |
| `TUYA_CLIENT_SECRET` | Access Secret проекта |
| `TUYA_DEVICE_ID` | ID датчика или список через запятую: `id1,id2,id3` (один ID — сработает автообнаружение, см. ниже) |
| `TUYA_REGION` | регион дата-центра: `us`, `eu`, `euw`, `cn` или `in` (по умолчанию `eu`) |

## Деплой через CLI (альтернатива)

```bash
cd vercel
npx vercel          # первый деплой, ответьте на вопросы, Root Directory уже текущая папка
npx vercel env add TUYA_CLIENT_ID production    # …и так все четыре переменные
npx vercel --prod   # финальный деплой с переменными
```

## Проверка

- `https://<проект>.vercel.app/` — дашборд
- `https://<проект>.vercel.app/api/readings?mock=1` — тестовые данные без устройства (удобно проверить деплой до настройки ключей)
- `https://<проект>.vercel.app/api/readings` — реальные показания

Если ключи не заданы или Tuya вернул ошибку, функция отвечает `200` с `{"status":"error", "error":"…"}` — дашборд покажет баннер с причиной вместо пустого экрана.

## Несколько датчиков

Логика та же, что и в Pages-версии: список через запятую в `TUYA_DEVICE_ID` либо автообнаружение всех датчиков аккаунта, если указан один ID (через Smart Home Management API с откатом на явный список при ошибке). Каждый датчик — отдельная секция на странице, ошибка одного не мешает остальным.

Особенность Vercel — лимит времени serverless-функции (10 с на Hobby): бюджет страниц журнала делится между датчиками (при 3–4 датчиках график каждого всё равно остаётся полным для типичного датчика с отчётом раз в 5–15 минут), плюс общий дедлайн — при нехватке времени история укорачивается, но текущие показания успевают собраться всегда. Если датчиков много (5+) — надёжнее GitHub Pages-вариант: там каждый сбор выполняется в Actions без жёсткого лимита.

## Отличия от GitHub Pages-версии

| | GitHub Pages | Vercel |
| --- | --- | --- |
| История данных | из журнала Tuya за 24 ч, снапшот каждые ~20 мин по расписанию Actions | из журнала Tuya за 24 ч, живой запрос при каждом открытии |
| Обновление без посетителей | да (cron в облаке GitHub) | нет (данные собираются только по запросу) |
| Хранение | `data/latest.json` коммитится Actions'ом | не нужно вовсе |
| Переменные | Secrets/Variables репозитория | Environment Variables проекта |
| Квота Tuya API | ~3–6 вызовов на датчик каждые 20 минут | ~3–6 вызовов на датчик на открытие страницы (повторы в течение 5 мин отдаются из edge-кэша — заголовок `s-maxage=300`) |

История ограничена 24 часами в обоих вариантах — это окно журнала Tuya Cloud. Если нужна накопительная история за недели — используйте локальную/серверную версию с SQLite.

## Приватный URL (опционально)

Функция не имеет собственного пароля: anyone с адресом видит показания. Если нужен доступ только для себя — **Project → Settings → Deployment Protection** включите protection для Production (просмотр потребует входа в Vercel), либо ограничьте доступ своим паролем через middleware. Ключи Tuya при этом всё равно не раскрываются — наружу отдаются только показания.
